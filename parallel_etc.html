Module 1 • Foundations

What is a Parallel Algorithm Model?

Normally, a sequential algorithm solves a problem one step at a time using a single processor—like one person doing all the chores alone. A Parallel Algorithm Model defines how we split a big computation into smaller pieces, assign them to multiple processors (or CPU cores) to run at the exact same time (concurrently), and coordinate them so the final answer is accurate and much faster.

🍳 Real-World Analogy: Preparing a 500-Guest Banquet

One solo chef cooking 500 meals takes all day. Hiring 4 chefs (Processors) lets them chop, grill, and plate simultaneously! However, the head chef must give instructions, chefs must share ingredients from the pantry (Memory Unit), and they must coordinate so the steak and sauce finish together (Synchronization).

5 Must-Know Parallel Terminologies

Explore each technical term alongside its simpler everyday meaning.

1. Task Unit of Work

Technical: A distinct unit of computation that can be executed independently or with limited dependencies.

Simpler: One specific chore on the to-do list, like "chop 50 onions" or "calculate the sum of row 1."

2. Processor Worker Core

Technical: A logical or physical computational unit (such as a CPU core or GPU shader) executing assigned tasks.

Simpler: The actual worker (chef) doing the work. More processors = more workers acting simultaneously.

3. Communication Data Exchange

Technical: The exchange of intermediate data or messages among processors via shared memory or networks.

Simpler: Chefs passing bowls of chopped ingredients to each other. Too much talking/passing slows down cooking!

4. Synchronization Order & Timing

Technical: Coordination of execution order across processors to respect task dependencies and prevent conflicts.

Simpler: Making sure the baker finishes baking the cake before the decorator starts putting frosting on it.

5. Granularity Work vs. Chat Ratio

Technical: The ratio of computation time to communication time. Coarse-grained = large independent chunks; Fine-grained = small chunks with frequent interaction.

Simpler: Slicing work into giant bricks (fewer trips to talk) vs. tiny sand grains (constant check-ins).

    Module 3 • Concurrency & Thread Safety

    Multithreading & Thread-Safe Data Structures

    Multithreading is a concurrency technique where a single running program (Process) launches multiple Threads (independent sequences of instructions) that all share the exact same memory (Address Space). On a multi-core CPU, threads run truly in parallel; on a single core, they rapidly take turns (interleave).

    🏠 Real-World Analogy: Roommates Sharing One Kitchen

    The House is the Process (shared address space). The Roommates are Threads. Because they share the same fridge and shopping list, if two roommates edit the grocery list at the exact same second without coordination, data gets corrupted (Race Condition)!

    All 8 Thread-Safe Data Structures

    How concurrent systems prevent race conditions, deadlocks, and data corruption across threads.

    1. Concurrent Queues

    Safe FIFO Message Passing

    Allows multiple threads to safely enqueue and dequeue items without manual locks.

    Analogy: A ticket dispenser where multiple customers take numbers without tearing the roll.

    Use Cases: Thread pool task scheduling, message buffering.

    2. Thread-Safe Collections

    Built-In Internal Safety

    Handles concurrent access internally (e.g., ConcurrentLinkedQueue using poll()) so data never corrupts.

    Analogy: A self-organizing library shelf that prevents two people from grabbing the same folder.

    Use Cases: Shared caches, lookup tables, web server active sessions.

    3. Blocking Queues

    Automatic Flow Control

    Pauses (put) producers when full and pauses (take) consumers when empty.

    Analogy: A 3-tray pass-through window between kitchen and waiter—chef waits if all 3 slots are full.

    Use Cases: Producer-consumer pipelines, bounded resource buffers.

    4. Lock-Free & Wait-Free

    Atomic Hardware Speed

    Avoids slow traditional locks (mutexes) by using hardware atomic operations (instant compare-and-swap).

    Analogy: Revolving doors instead of a single locked door—nobody gets stuck waiting in line.

    Use Cases: Ultra-low latency trading, real-time systems, high contention.

    5. Immutable Structures

    Read-Only & Versioned

    Cannot be modified after creation. Updating returns a brand-new copy, making it 100% thread-safe.

    Analogy: Printing a new edition of a textbook instead of erasing words in everyone's copy.

    Use Cases: Functional programming, shared app configurations, memoization.

    6. Sync Stacks & Lists

    Locked LIFO / FIFO Order

    Wraps standard stacks or linked lists with locks/atomics so only one thread modifies pointers at a time.

    Analogy: A spring-loaded plate stack with a lid that only opens for one person at a time.

    Use Cases: Undo/redo history, browser navigation stacks.

    7. Priority Queues

    Urgency Over Arrival Order

    Retrieves elements by highest priority rather than insertion order while staying thread-safe.

    Analogy: Hospital ER triage—urgent emergencies are treated before minor sprains.

    Use Cases: Urgent task schedulers, network packet routing.

    8. Read-Write Locks

    Many Readers, One Writer

    Allows multiple threads to read simultaneously, but grants exclusive access when a thread writes.

    Analogy: A museum painting—50 visitors can look at once, but everyone steps out when the restorer paints.

    Use Cases: Read-heavy databases, shared routing tables.

    Module 4 • Efficiency & Scalability

    Algorithmic Complexity & Big O Time Complexities

    Algorithmic Complexity measures how the number of steps (operations) an algorithm takes grows as the input data size (n) gets larger. Instead of measuring seconds (which depend on how fast your laptop is), computer scientists use Big O Notation — O(f) (asymptotic notation) to describe the growth rate of work.

    📚 Real-World Analogy: Finding a Name in a Contact Book

    If a contact book grows from 10 names to 10,000 names (n), how many pages must you flip? Checking the very first page is always 1 step (O(1)). Splitting the alphabet in half each time takes only ~14 flips (O(log n)). Reading every single page takes 10,000 flips (O(n))!

    Quick Real-World Analogy Cheat Sheet

    Connect every technical term to everyday life.

    Parallel Algorithm Model: A team of chefs cooking a 500-guest banquet simultaneously instead of one chef working alone.
    Granularity (Coarse vs. Fine): Giving each chef a whole dish to finish (Coarse = less talking) vs. asking for approval after every carrot slice (Fine = high communication overhead).
    Data-Parallel (SIMD): 4 teachers grading 1,000 exams using the exact same answer key on 250 papers each.
    Task Graph (DAG): Building a house—plumbing and wiring can happen in parallel, but both must wait until the walls are framed.
    Work Pool vs. Master-Worker: Coffee shop baristas pulling tickets from a shared rail whenever free (Work Pool) vs. an orchestra conductor assigning specific sheet music to players (Master-Worker).
    Pipeline Model: A sandwich assembly line (Bread → Meat → Veggies → Wrap) where 4 sandwiches are worked on at once at different stations.
    Multithreading & BlockingQueue: Roommates sharing one kitchen (Address Space) and a 3-slot pass-through counter that makes the chef wait if full and the waiter wait if empty.
    Big O Time Complexity O(f): Measuring how many extra steps an algorithm takes as the pile of data (n) grows from 10 items to 1,000,000 items.
